# UI/UX implementation contract
Use neutral placeholder identity and a configurable working name (`APP_NAME`, A06) until brand supplied. Proposed tokens: navy #12263A, teal #176B80, background #F6F8FA, text #172B3A, error #B42318, success #067647. System font plus Arabic-compatible font; 4px spacing base, 8/12px radius. Use consistent button hierarchy, semantic statuses with text (never color alone), WCAG AA contrast target, keyboard navigation, focus ring, labelled inputs and accessible errors. Responsive widths 360, 768, 1024, 1440; no horizontal page overflow; tables scroll or render cards on mobile.

Layout: global header with search (buyer), workspace switcher, unread alerts and profile. Desktop role sidebar; breadcrumbs on detail pages. Mobile bottom nav and sheets for filters. Admin tables support pagination, column filters and details drawer. Checkout and quote acceptance use explicit review step; show quantities, AED, tax, fees, seller terms and final total before confirmation. Never display unapproved commercial policy text.

Shared screen contract: skeleton while fetching; empty state with contextual action; error with retry and request reference; forbidden page without leaking entity existence; disabled action explains prerequisite; success reflects actual persisted response. Mutations disable double click, use idempotency keys where required, and keep form inputs on recoverable failure. Confirm deletion/archive, acceptance, cancellation, refund and role changes. Inline field errors with first invalid field focus. No toast-only critical error. Use server pagination with stable ordering. Store filter state in URL; never store private files or tokens in browser localStorage.

Localization: all strings translation keys, Arabic RTL at document root, logical margins and directional icons, bilingual catalog fields with fallback, no hardcoded English text. Currency via Intl AED, timestamps in Dubai, UTC in API. Arabic and English search normalize case/diacritics without altering original records. Support phone +971 and international format validation (eligibility policy separate).

Navigation links and screens are listed in buyer/seller/admin docs; implement all MVP routes with actual API integration. Phase 2 screens must be hidden by feature flags, not clickable placeholders. Design review includes onboarding, product, quote comparison, checkout, order timeline, admin review and mobile layouts.
